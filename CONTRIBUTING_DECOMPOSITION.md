# Как декомпозировать работу в Hoarbound

Единый принцип: **PRD → Epic → User Story → Task → Subtask**.

| Уровень     | Где живёт                                      | Пример из репо |
|-------------|------------------------------------------------|----------------|
| PRD         | `PRD.md`                                       | этот файл + PRD |
| Epic        | Milestone + (опционально) issue по шаблону `epic.md` | milestone "First Exit" |
| User Story  | issue по шаблону `user_story.md`               | «Как игрок, я хочу…» |
| Task        | дочерний issue / PR по шаблону `task.md`       | #74, #75, #76 |
| Subtask     | чек-лист внутри Task (НЕ отдельный issue)      | пункты чек-листа |

## Правила

1. **Epic не начинают без критериев готовности.**  
   Если не можешь сформулировать чек-лист «milestone закрыт, когда…» — рано заводить milestone.

2. **Story = одна ценность игрока.**  
   Если в формулировке «я хочу X и Y» — это две story, а не одна.

3. **Task всегда содержит раздел «Не делать в этом PR».**  
   Это главный защитник от scope creep.

4. **Subtask — не issue.**  
   Это чек-лист внутри Task. Каждый пункт ideally закрывается одним коммитом/диффом + headless-тестом (где возможно).

5. **«Вне scope» обязателен** на уровне Epic, Story и Task.  
   Явно исключённое не нужно защищать в код-ревью каждый раз заново.

6. **Приоритет относительно текущего vertical slice обязателен.**  
   В User Story явно указывай: Blocking for First Exit A? / P0 / P1 / Later.

7. **Роль Grok.**  
   Grok (`grok`) может предлагать декомпозицию, писать/править docs, заводить planning-issues и проводить audits.  
   Grok **не** создаёт implementation-tasks и не пишет gameplay-код без явного запроса автора.

8. **Coordination, не дублирование.**  
   Хендоффы между агентами — в issue #1, а не в теле task.

## Когда поднимать уровень, а не расширять существующий

- Issue вырос за 8–10 пунктов чек-листа → скорее всего это Story, раздели на Tasks.
- Task не помещается в один PR без «и ещё вот это» → вынеси лишнее в отдельный Task той же Story.
- Появился принципиально новый player fantasy (не вариация существующего) → кандидат в новый Epic, не Story внутри текущего.
